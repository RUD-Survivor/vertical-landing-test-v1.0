# 地球地形结构性修复与验证

验证日期：2026-10-12。环境：Windows、MSVC C++17、Vulkan 验证层、NVIDIA GeForce RTX 4060 Laptop GPU。

## 修改内容

- `terrain_height_shared.glsl` 同时被 C++ 和 GLSL 编译，供碰撞、地形、海面和阴影使用。去掉 CPU 再除以 255、CPU 独有沙丘/小丘/湖面填平和不同的山脉噪声公式；碰撞返回真实床面，包括负海拔海底，水面独立绘制。
- 使用整数格点哈希，统一经纬度、周期经线、极点行和显式纹素插值。纹理分辨率来自实际数据，消除 512×256 硬编码和双重过滤。Strahler 与流向按离散原始值读取。
- 在固定 512×256 地理网格上对精化床面求水文，保留原始床面作为参考。RGBA 分别为填洼水位、原始床面、原始 Strahler、D8 流向。水深由填洼差值约束，避免把未解析的地形起伏当成大面积湖泊。积水上限为 60m，陆地水面的数值单位按 `maxElevation` 转换。
- 删除与相机叶节点绑定的局部缓存、继承和同步洪泛计算。水文不再因 LOD 分裂/合并重建，也不再覆盖气候 moisture 数组。保留的通用局部洪泛函数正确写入边界种子，数值回归验证 8×8 平面测试的 36 个内部单元。
- LOD 使用地形和水面中较近的距离，加入分裂/合并滞回及 8 步父网格三角面渐变。相邻叶节点传递层级差和渐变阶段，在同一条粗网格边上插值，覆盖立方体面之间的边界。拼接后仅保留 3m 栅格误差保护边，避免深裙边形成轨道暗线；暂态极端层级差保留深裙边回退。
- 顶点使用 CPU 双精度生成的补丁锚点和有理化球面差分，避免直接相减行星尺度坐标。128 字节 push constants 的矩阵底行存储锚点，旋转和行星平移保持可用；只修改 push constants 副本。
- 主地形使用实际渲染三角面的导数法线，包含真实坡度和渐变。细节几何最大偏移为 15cm，波长至少 32m；远景过滤在整颗星球上使用统一权重，避免补丁边缘的不同高度。
- 加入地平线和视锥剔除。包围体由纹理梯度、噪声导数上界和全局高度范围共同约束；阴影单独采集近处屏幕外投射体，避免视锥剔除丢失阴影。
- 增量构建跟踪 C++ 共用的 `.glsl`，地面碰撞相关编译单元也跟踪 render 目录，防止 CPU 与着色器版本错配。

## 数值验证

执行 `tools\build_terrain_validation.cmd`，再从项目根目录运行 `build\tests\terrain_validation.exe`。验证程序读回 GPU 实际计算值，不使用源码文本匹配代替数值结果。

测试数据：8×4 常量海洋、64×32 连续海岸、256×128 连续山地、真实生成的 256×128 地形及 512×256 水文。每组包含 4496 个高度/水位/法线样本及 1311 个锚点/渐变/裙边/拼接几何样本，共 23228 个 GPU 样本。

本次结果：

- 真实生成地形的 CPU/GPU 床面与水位最大差：**0.257492m**，通过阈值为 0.5m。单精度超越函数及计算顺序仍有微小差异，没有宣称逐位相同。
- 相对独立双精度球面与三角插值参考的几何最大差：**0.001377m**，通过阈值为 0.02m。覆盖四条边、1–3 级邻居差和三个邻居渐变阶段。
- CPU/GPU 解析法线最大夹角差：**1.194592°**，通过阈值为 3°。主渲染采用实际三角面的导数法线。
- 微几何过滤的最大床面变化：**0.146866m**，满足 15cm 限制。
- 经线两侧差值小于 1m；两极数值有限；发射场中心床面为 5m。
- 32700 个独立床面/水面包围体采样全部位于剔除包围体中。
- 静止相机亚毫米抖动测试：零新增分裂、零合并；远离星球后合并回六个根节点。
- 64 帧往返 LOD 场景：50 次分裂、37 次合并；所有帧均未发现被周围地面包围的深度空洞。
- 实际阴影图 GPU 读回：四个近地场景均产生有效地形深度，所有 4096×1024 深度值有限且在 [0,1] 内；屏幕外附近投射体独立提交。
- 数值、画面、阴影及资源销毁阶段：**Vulkan 验证错误为零**。

## 画面验证

通过生产 `VkRenderer3D`、地形/海面/阴影管线和大气后处理，在隐藏窗口中真实渲染并读回 GPU 像素，输出未经修改的 PPM。PNG 为 PPM 的无损转换，合成预览仅调整缩略图尺寸与标签。

五个场景共 **112 帧**：发射场、约 10.8km 山地、海岸、400km 轨道和往返 LOD。画面检查过程中发现并修复了近地碎斑、粗水文误判山坡水面及轨道裙边暗线。最终检查了近地、山地、海岸、轨道和切换首尾截图；同时检查 HDR 有限/非负、深度范围、实际地形覆盖和深度空洞。

输出位于 `build/tests/`：

- `terrain-verification-overview.png`：四个静态场景预览。
- `terrain-{launchpad,mountain,coast,orbit}-0.png` 与 `-11.png`：移动相机的首尾帧。
- `terrain-lod-transition-0.png` 与 `-63.png`：LOD 往返首尾帧。
- `terrain-*-before-water.png`：海面合成前的原始地形阶段，用于定位地形与海面问题。
- `terrain-validation.txt`、`terrain-validator-run.log`：完整数值与每场景 GPU 时间。
- `terrain-ocean-regression-run.log`：原有海面轨道回归。
- `terrain-release-build.log`：最终发布构建日志。

固定静态场景中的主绘制剔除了约 30–45% 的叶节点，另行保留阴影所需的附近投射体。GPU 时间是 960×540 验证场景的几何和海面时间，不包含全游戏 CPU、UI 与云后处理；初次执行、设备动态频率及并行构建会影响峰值。没有以这些数值宣称完整游戏帧率。

## 范围与限制

水文仍是固定分辨率的区域模型，不是米级河道或流体模拟。父网格渐变及远景微几何过滤允许明确受限的显示误差；碰撞始终查询完整床面。生态群系、植被模型与分布另属此前检查出的独立问题，本次没有将其扩展为景观资产开发。

渲染验证使用真实生产管线及固定相机测试场景，未将其表述为完整交互飞行、所有天气与所有摄像机状态均已人工验收。

## 实际运行地形缺失回归修复（2026-10-12）

实际首次飞行初始化曾直接把物理常量 `EARTH_RADIUS=6371000`（米）传给地形。地形高度、包围球和渲染矩阵使用千米，绘制半径为 6371；因此 CPU 包围球中心被置于约 637 万千米的半径上，细地形块被视锥错误剔除。此前独立验证直接初始化为 6371，未覆盖这条物理到渲染的启动路径。

增加 `QuadtreeTerrain::fromMeters`，实际启动和生产验证都通过该工厂转换单位。另将六个面的 LOD 更新与绘制提取分为两个阶段，确保边缘拼接查询到同一帧的邻面状态。

新增回归在两个浮动原点下复现旧单位错误造成的细块缺失，并确认转换后块可见。新增 144 帧冷启动场景，不预先稳定 LOD；连同原有五组场景，共 256 帧。CPU/GPU 数值验证、包围球采样、深度空洞检查均通过，Vulkan 验证错误为零。人工检查 `terrain-startup-0.png` 和 `terrain-startup-143.png`：启动粗网格和最终发射场地面均可见。发射场附近本身是平坦区域，启动过程仍能看到远方粗网格轮廓逐渐收敛。

发布构建通过，新版本已生成到 `build/release/Stella_Ascend.exe` 并复制到根目录。仍未将上述固定场景验证表述为完整交互飞行验收。
