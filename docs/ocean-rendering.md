# Vulkan 水面结构与验证记录

## 实际改动及适用路径

原飞行场景使用地形补丁替代 Earth 球体，海床被抬到海平面，洪泛高度又提前混入地形，最终通过地形蓝色漫反射表现水面。这使光学深度、独立水面法线及反射输入缺失。新的 `VkOceanSystem` 将海床和水面分开绘制，并接入现有大气、云影和 TAA。

覆盖 Vulkan 飞行场景中有地形补丁的 Earth。旧 OpenGL 路径和无地形补丁时的 `earth.frag` 球体材质未转换。CPU 地形碰撞仍沿用现有地表高度约定，波浪位移是视觉模型，不是船舶浮力模拟。

## 帧内顺序及资源契约

1. 不透明几何写 HDR RGBA16F 和 D32，包括实际海床。
2. 水面保存不透明 HDR/D32 快照；独立绘制水面，写水面深度及 R8 TAA 响应掩码。
3. 大气根据水面深度合成；复用的大气颜色快照在此阶段重新复制。
4. 体积云合成；云影沿用现有级联图集契约。
5. TAA 根据响应掩码提高动态水面当前帧权重，再呈现交换链图像。

水面绝不读取自身正在写入的颜色或深度。海床快照用显式 DEPTH aspect 做复制屏障；大气 LUT 描述符保持 GENERAL 布局。每帧槽的描述符在绑定前一次性更新；TAA 只更新当前 ping-pong 集，避免修改另一帧正在使用的描述符。无地形时仍清空响应掩码，避免场景切换留下水面历史。

天空反射使用 64×32×32 RGBA16F 表，按局部视线高度、太阳高度和相对方位采样。它按大气物理配置缓存，不依赖相机 SkyView。配置改变时重新烘焙并同步；采样器三个轴均为 CLAMP_TO_EDGE。表中是单次散射近似，不是完整多次散射天空。

额外全屏资源为 D32 海床快照和 R8 掩码，约 5 字节/像素；天空表约 0.5 MiB。不透明 HDR 快照复用现有资源。地形高度由 RGBA8 改为 RGBA32F，纹理内存增加四倍，消除浅水高度的 8 位量化。

## 单位和数值约定

- 世界空间及大气积分用 km；水深、波长、振幅及水体消光用 m。
- 归一化海平面为 0.45；海床连续映射到最低 −6 km，陆地映射沿用最大海拔参数。
- 海洋水位为 0 km；陆地积水取原始床面与洪泛高度的最大值；先保留床面再算水深。
- 水深不超过 0.02 m 的片元丢弃；浅水波浪在 0–3 m 平滑衰减。
- 三个长波频带用于径向几何位移，十二个频带用于切向法线；波向在行星局部三维空间定义，无经纬度极点图表。
- CPU 双精度时间和双精度相位计算，归约到 ±π 后传 float。快照保留双精度时钟，避免长期运行先被 float 截断。
- 像素足迹超过可解析波长时，将被滤掉的斜率能量转入 GGX 粗糙度方差，抑制轨道视角的闪烁。
- 水折射率 1.333；Fresnel 与 Beer–Lambert 消光分离反射和透射。使用有界 GGX、太阳角半径正则化、深水读取跳过和有界 SSR。
- 深度重建和 TAA 重投影均匹配 Vulkan Y 翻转及现有 GL→Vulkan 深度映射。

当前球面坐标、模型矩阵和 GPU 几何仍为 float。CPU 相位归约改善时间与原点稳定性，但不等于解决了全球球面坐标的亚米级精度问题；更严格的近距离几何精度需要进一步采用局部切平面或高低位坐标。

## 分阶段验证（2026-10-10）

`tools/run_ocean_numerics.cmd` 的五阶段全部通过：

1. 海岸映射连续、6 km 海水深度、4.545 m 湖泊、干地水深为零。
2. Fresnel 有界且单调、反射/透射分配、0–10 km Beer–Lambert 单调消光。
3. 相位换锚最大误差 2.11e−7 rad、总解析斜率上界 0.430、两极与 1e7 s 时钟；长时钟仍能分辨 16 ms。
4. 波浪足迹过滤前后解析斜率能量守恒，轨道足迹全部转入未解析方差。
5. 深度重建和移动相机历史投影往返误差低于 1e−9（CPU 双精度参考）。

GPU 验证程序由 `tools/build_ocean_gpu_validation.cmd` 构建，运行 `build/tests/ocean_gpu_validation.exe`。实际设备为 NVIDIA GeForce RTX 4060 Laptop GPU，20 个场景通过：深海昼夜、干地、浅水、轨道、关闭水面、缩放、100 km 原点偏移、浅湖、海岸、日落、水下看水面、720p、完整链路首帧/历史帧/两个后续帧、零散射配置、南极、长时钟。

完整链路四帧执行了真实不透明绘制、水面、大气、体积云、TAA 解析及隐藏窗口交换链呈现，交替两个帧槽；最后一帧包含 10 cm 相机移动。HDR、响应掩码和两份深度均由 GPU 回读，检查有限非负 HDR、有效覆盖、干地无覆盖、昼夜光照及水面遮挡海床。Vulkan 验证层错误为零；存在未使用顶点属性/输出的性能提示。

Release 全部着色器及 C++ 构建成功；原有 Python 测试 12 项通过。GPU 测试使用小型合成地形和固定相机，并非真实地图的美术验收或多帧拖影的定量误差测试。PPM 是回读 HDR 的简易色调映射预览；海岸粗地形案例用来检测干湿覆盖，不代表最终地形 LOD 视觉质量。

## 性能验证与修复

计时范围为水面 `render()`，包括快照复制、必要的 LUT 工作及绘制，不包括整个游戏帧。最终回归中，1280×720 全屏水面约 3.05 ms；包含云影的历史及后续帧分别为 4.77 / 2.78 / 2.20 ms。笔记本时钟及其他 GPU 工作会影响这些数字，不能外推为游戏帧率。

未优化的水面 SPIR-V 在云影开启后达到 16–21 ms。启用 `glslc -O` 后，函数局部变量及函数调用相关指令计数由 206 降至 6，实测消除了这一性能退化。三个新水面着色器的优化标志已写入 `compile_shaders.bat`，没有删减云影规则。

首次天空表/配置烘焙会产生额外开销：测试中首次水面约 15 ms，零散射配置切换约 9.6 ms；这些帧不能归入稳态预算。缩放沿用现有设备等待机制，资源退休后再重建。所有生成的测试二进制、图像和日志放在忽略目录 `build/tests/`。

## 当前效果边界

这是独立水面几何、光学、反射、云影和时域处理的完整渲染链路，波浪采用固定解析频带。尚未实现 FFT 风浪谱与风场驱动、持久泡沫输运、船舶尾迹/浮力、完整水下体积及动态云层在水中的反射。SSR 只能反射屏幕内不透明物体，离屏回退到天空表；湖泊反射大气按海平面近似。现有地形网格和 LOD 决定海岸几何细度。

验证证明链路执行、数值边界和资源使用在上述场景中正确；真实飞行视角下的光照曝光、海岸细节和整体画面仍需要视觉验收。

## 色彩回归补充：黑色棋盘问题（2026-10-10）

此前的有限值、非负值和最大亮度检查未覆盖色彩完整性，不能据此宣称颜色验收通过。用户指出的 `ocean-full-chain-steady2.png` 是中间 HDR 经单独 Reinhard/幂函数转换的预览，并非实际交换链截图。

新增 GPU 逐阶段回读后，修复前完整链路首帧的数据为：水面平均线性亮度 0.009973，大气后 0.010328，云合成后 0.000652；云合成使 93.75% 像素变黑。云重建错误地认为首帧历史有效，4×4 Bayer 更新仅刷新一个像素，其余十五个像素从未生成的历史读取散射和透射数据。

修复包括：新建/重建云纹理时使历史无效，首帧走当前低分辨率结果上采样来初始化所有像素；关闭云及缺少有效场景时使历史失效。新增的云历史重建及关闭后恢复场景验证了这些边界。

另一个问题是最终 TAA 直接向 BGRA8_UNORM 交换链写线性颜色。SRGB_NONLINEAR surface color space 不会让 UNORM attachment 自动编码。现在在 TAA 线性混合结束后，根据 attachment 格式执行一次分段 sRGB 转换；若 attachment 为 SRGB 格式则交给硬件，避免重复转换。色彩对照还发现 blendFactor=1 在运动分支会被错误限制为 0.9，一并修正了当前帧模式。

测试现在包含 22 个 GPU 场景。完整链路增加水面、大气、云合成和真实交换链图像回读。固定的近地向下看水面场景中，云在不透明水面之后，不应抹去水面颜色；此场景加入云后亮度保留检查和日间呈现黑像素检查。首帧使用当前帧模式，逐像素比较交换链 RGB8 与 CPU sRGB 参考，最大误差为 1/255。日间呈现黑像素比例为 0%；修复后首帧大气与云后亮度均为 0.010328。后续帧仍受正常云影衰减，云合成自身不再抹去水面。

新的 `*-display.ppm`/PNG 直接来自交换链 RGB8 回读，不施加额外曝光或色调映射。保留原有黑色 PNG 供对照；`ocean-full-chain-steady2-display.png` 是修复后实际呈现结果。测试通过且 Vulkan 错误为零，不代表画面已经达到真实海洋的色彩标准：当前照明尺度和曝光仍缺少真实日间参考标定，水面仍偏暗，天空反射也保留单次散射近似。色彩完整性回归、显示转换正确性与最终美术/物理色彩验收应分别判断。

## 偏暗分项诊断（2026-10-10）

新增 `VkOceanSystem::debugView`，默认 0 保持正常水面；1–4 分离反射、水体、太阳高光和泡沫的最终加法贡献，5–8 检查原始反射天空、天顶、反射低于地平线比例和 Fresnel，9/10 分别关闭 SSR、短波法线，11 检查 18% Lambert 灰卡，12 检查太阳可见度，13 使用现有近地大气显示变换检查同一个天顶输入。它们用于辐射诊断，不是额外美术增益。

固定晴空、相同波浪时刻和相机的 GPU 水面亮度 Y 为 0.00997350。分项反射 0.00625273、水体 0.00311423、太阳高光 0.00004600、泡沫 0.00056080，总和与原结果匹配，偏差小于 0.5%。反射约占 62.7%，水体约占 31.2%；太阳方向不在当前视角的反射高光带内，不能把小高光值直接判为照明错误。

SSR 关闭后的 Y 完全相同；关闭短波法线后 Y=0.00915980，反而稍暗。低于地平线的反射约 1%，不是画面整体偏暗主因。Fresnel 的屏幕平均值约 0.189；真实海水正视低反射率会压低亮度，但本场景也有掠射像素，不能用单一 F0 解释全画面。

发现三项独立原因：

1. **显示天空与水面反射尺度不一致。** 同一天顶天空，水面使用原始辐射值 Y=0.01081512；按现有大气 `ACES(scatter×InnerExposureNear)` 处理后，Y=0.14091209。Near 默认 10。大气显示路径在合成前做曝光和非线性映射，而水面、地形及云又使用不同的照明尺度，最后 TAA 只做 sRGB 编码。sRGB 转换正确并不能修复这种辐射尺度不一致。上述对照使用同一份水面天空表来隔离显示变换，不宣称它与相机 SkyView 的多次散射结果完全相同。
2. **水体天空照明低估。** 代码用单一天顶辐射值乘 0.25 近似各向同性水体散射源。GPU 天空表回读后，通过 32×64 方位/高度半球余弦积分，天空辐照度 RGB 为 (0.03007711, 0.05481242, 0.09367608)，分别是 π×天顶亮度的 1.720 / 1.551 / 1.354 倍。这是输入环境光的低估，不意味着整幅水面颜色应按同一倍率放大。
3. **默认厚云遮蔽直射。** 默认低云 coverage=1、density=1，另启用高层云。测试区域太阳可见度为 0，水面 Y 从晴空 0.00997350 降到 0.00648029，约降低 35%。低云 density=0 且关闭高层云后，重新生成的图集将太阳可见度恢复到 1。因此不是读取错误黑图集；这是该固定区域和配置的真实积分结果，不能泛化为整颗地球都被遮蔽。

18% Lambert 灰卡参考若使用半球积分天空光而不是天顶近似，输出 Y=0.04004967。**如果**选择将该参考灰卡映射到显示前的 0.18 线性中灰，需要统一曝光约 4.4944（+2.1681 EV）。这是一个明确的目标映射假设，不是根据真实太阳 lux、光谱或相机参数完成的绝对校准，也不是给水面单独乘 4.5 的依据。

本轮维持默认水面色彩，完成原因隔离，不将调亮当成真实颜色验收。结构性校准应先统一太阳辐照度和环境辐射亮度约定，将天空、水体、地形及云维持在线性空间合成，然后统一曝光/色调映射和一次显示转换；水体天空源应来自余弦半球辐照度积分。直接把反射输入套 ACES 或只把水面乘十，会把非线性变换放在 Fresnel/散射之前，掩盖尺度问题。

最终 39 个 GPU 场景（含分项诊断和零云消光对照）通过，分项加法守恒检查、显示转换检查和 Vulkan 验证层均通过。日志为 `build/tests/ocean-radiometry-final.log`；半球积分与灰卡结果也写入该日志。

辐射亮度与辐照度、余弦积分及反射方程的物理定义参考 [PBRT: Radiometry](https://pbr-book.org/4ed/Radiometry%2C_Spectra%2C_and_Color/Radiometry)、[PBRT: Surface Reflection](https://pbr-book.org/4ed/Radiometry%2C_Spectra%2C_and_Color/Surface_Reflection)；太阳辐照度与天空辐射亮度区分参考 [Bruneton atmosphere model API](https://ebruneton.github.io/precomputed_atmospheric_scattering/atmosphere/model.h.html)。

## 统一辐射与呈现链路修正

以下实现取代上节“维持默认色彩、仅隔离原因”的阶段状态。当前 Vulkan 地形／海洋及大气壳内、壳外正常绘制路径采用相对线性辐射单位：单位太阳辐照度为 1.1，乘场景快照的太阳强度；天空表仍按单位太阳烘焙，运行时缩放。云的独立太阳美术倍率默认从 3 改为中性 1。水体太阳光使用白色入射光，颜色衰减由大气透射与水体吸收产生。

新增 `ocean_irradiance.comp`，从 64×32×32 天空辐射表积分 32 个太阳高度的余弦半球辐照度。32×2 RGBA16F 表的第一行保存入射辐照度，第二行加入介电入水透射；体散射使用第二行，泡沫与灰卡使用第一行。它与天空表同时按大气 profile 缓存，太阳强度变化无需重烤。表内存为 512 字节；额外积分在 profile 变化时进行，不在每个水面片元中循环。

水体保留单层各向同性散射近似，源项为入水辐照度除以 4π；这还不是完整水下方向输运。泡沫和地形使用 Lambert 的 1/π 归一化。地形天空项仍是常量环境辐照度近似，未接入海洋的半球表。普通大气合成去除自身曝光、limb 美术增益与提前 ACES，改为 `solarIrradiance × scatter + scene × transmittance`。大气旧曝光／limb 字段保留 ABI，相关无效滑条移除；专用调试可视化保留自己的编码，不属于正常颜色路径。

TAA 的输入与历史保持线性 HDR；最终 resolve 在时间混合之后统一曝光、ACES，再做一次 sRGB 编码。UNORM 显式编码，SRGB 附件由硬件编码。飞行默认曝光为 3.25，可在大气调参面板调整；非飞行菜单保持原有输出行为。使用归一化日照下的 18% 灰卡作为曝光参考：测试灰卡线性 HDR Y=0.04101919，最终映射后的线性 Y=0.18561636。此为明确的相对灰卡标定，没有真实 lux、相机光谱或摄影参考标定。

验证分阶段完成：

- CPU 共 8 阶段：原有水位、Fresnel、相位／极点、坡度过滤、重投影；新增余弦半球积分与 Lambert 能量守恒，数值辐射输运与解析吸收／散射解的比较，最终曝光与显示转换的单调性、黑值、高光及 sRGB 分段边界。原有 12 项 Python 测试也通过。
- GPU 共 44 场景：32 个太阳高度的两行积分与 CPU 独立三线性积分比较，最大相对误差 0.478%；32×64 与加密至 128×256 的余弦积分最大相对误差 0.0507%。入水透射不增加辐照度。包含原有夜间、极点、轨道、浅水、岸线、零散射、长时钟、浮动原点、resize、云历史与水面分项守恒验证。
- 补充太阳强度 0／2／10：零日照水面 HDR 为零；倍率分别为 2.000000、10.000153，单位太阳缓存不失效。晴天和灰卡真实交换链像素与 CPU 曝光→ACES→sRGB 参考最大误差 1/255，黑洞像素比例为零。
